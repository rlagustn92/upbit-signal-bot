# 코인 시그널 봇 (업비트 자동매매)

업비트 OPEN API로 실제 시세를 받아, 정한 전략에 따라 **모의투자(PAPER)** 또는 **실전(LIVE)** 으로 사고파는 자동매매 프로그램입니다.

> ⚠️ 자동매매는 수익을 보장하지 않습니다. 손실이 날 수 있으며, 프로그램(서버)이 꺼져 있으면 아무것도 하지 않습니다.
> 처음 실행하면 **항상 모의투자**이고, 실전은 여러 단계를 거쳐 직접 허용해야만 켜집니다.

---

## 1. 설치 방법

1. **Node.js 24 LTS** 설치 — https://nodejs.org 에서 "LTS" 버전을 받아 설치합니다.
   - 설치 확인: 터미널(PowerShell)에서 `node -v` → `v24.x.x` 가 나오면 됩니다.
2. 이 폴더에서 패키지를 설치합니다.

```bash
npm install
```

## 2. 실행 방법

### 딸깍 실행 (윈도우)
| 파일 | 용도 |
|---|---|
| `start.bat` | **테스트 실행** — 처음이면 자동 설치 → 서버 실행 → 브라우저(http://localhost:5173) 자동 열기 |
| `start-24h.bat` | **24시간 운영** — 빌드 후 http://127.0.0.1:8787, 서버가 죽으면 자동 재시작 |
| `autostart-install.bat` / `autostart-remove.bat` | 윈도우 켤 때 자동 시작 등록/해제 |
| `connect-cloud.bat` | 오라클 클라우드 서버에서 돌리는 봇 화면 열기(SSH 터널) |

24시간 무료로 돌리는 방법(내 PC vs 오라클 클라우드 무료 서버)은 **[docs/DEPLOY.md](docs/DEPLOY.md)** 를 보세요.

### 명령어로 실행
개발/평소 사용 (백엔드 + 화면을 함께 실행):

```bash
npm run dev
```

- 브라우저에서 **http://localhost:5173** 을 엽니다.
- 터미널 창을 닫으면 프로그램이 멈춥니다. 봇 상태는 저장되어 있어서 다시 실행하면 이어서 동작합니다(재시작 복구).

24시간 운영용 실행(빌드 후 http://127.0.0.1:8787 에서 화면까지 제공, 서버가 예기치 않게 죽으면 자동 재시작):

```bash
npm start
```

## 3. 환경변수 설정 (.env)

`.env.example` 을 복사해 `.env` 를 만듭니다. (`.env` 는 git에 올라가지 않습니다)

```bash
copy .env.example .env
```

| 변수 | 설명 | 기본값 |
|---|---|---|
| `UPBIT_ACCESS_KEY` / `UPBIT_SECRET_KEY` | 업비트 API Key (화면에서 등록해도 됨. 화면 등록이 우선) | 비어 있음 |
| `SERVER_PORT` | 백엔드 포트 | 8787 |
| `DATABASE_PATH` | SQLite DB 파일 | ./data/bot.db |
| `APP_ENCRYPTION_KEY` | 화면에서 등록한 Secret Key 암호화 키(64자리 hex). 비우면 `data/master.key` 자동 생성 | 비어 있음 |
| `PAPER_INITIAL_KRW` | 모의투자 시작 원화 | 10,000,000 |
| `LIVE_TRADING_HARD_LOCK` | **true면 어떤 경우에도 실제 주문이 나가지 않음** | true |
| `LOG_LEVEL` | debug / info / warn / error | info |

> `data/` 폴더(DB, 로그, 암호화 키)도 git에서 제외되어 있습니다. 만약 실수로 API Key가 git이나 다른 곳에 올라갔다면 **즉시 업비트에서 그 Key를 삭제하고 새로 발급**하세요.

## 4. 업비트 API Key 발급 방법

1. 업비트 웹 → 로그인 → **마이페이지 → Open API 관리**
2. 권한 선택 — 아래처럼만 체크합니다.

| 권한 | 체크 | 이유 |
|---|---|---|
| 자산조회 | ✅ | 잔고/보유 코인 확인 |
| 주문조회 | ✅ | 주문 가능 정보, 주문 상태 확인 |
| 주문하기 | ✅ | 실전 매매(LIVE)에 필요 |
| **출금하기** | ❌ **절대 체크하지 마세요** | 이 프로그램에는 출금 기능이 없습니다 |
| 출금조회 / 입금 관련 | ❌ | 필요 없음 |

3. **허용 IP**: 이 프로그램을 실행하는 PC의 공인 IP를 등록해야 합니다. (등록 안 하면 "IP가 허용되지 않았어요" 오류)
4. 발급된 **Secret Key는 이때 한 번만 보입니다.** 바로 복사해 두세요.

## 5. API Key 등록 & 권한 확인

1. 화면 상단 **업비트 API 연결** 탭 → **API Key 등록**
2. Access Key / Secret Key 입력 → **저장하고 연결 확인**
   - Secret Key는 이 PC의 서버에만 **암호화되어** 저장되고, 화면에 다시 보이지 않습니다.
3. 자동으로 **연결 상태 테스트**가 실행되어 실제 업비트에 물어본 결과를 보여줍니다.
   - 시세 조회 / 내 계좌 조회 / 주문 조회 / 주문하기 각각 "가능 / 권한 없음"
   - 주문하기 권한은 업비트 **주문 생성 테스트 API**로 확인합니다 → **실제 주문은 생성되지 않습니다.**
   - 출금 권한은 프로그램이 확인할 수 없으니 업비트 화면에서 꺼져 있는지 꼭 직접 확인하세요.

## 6. 모의투자(PAPER) 사용 방법

- API Key가 없어도 모의투자는 바로 됩니다(실제 시세 사용).
- 가상 원화 1,000만 원(설정 가능)으로 사고팝니다. **업비트에는 아무 주문도 보내지 않습니다.**
- 체결 방식: 시장가는 현재가에 0.05% 불리하게, 지정가는 실시간 체결가가 그 가격에 닿으면 체결. 수수료 0.05% 적용.
- **업비트 API 연결** 탭 → "가상 원화 초기화"로 처음부터 다시 할 수 있습니다(모의 봇을 모두 끈 상태에서).

## 7. 실전(LIVE) 사용 방법 — 마지막 단계에서만

실전은 4중 안전장치를 모두 풀어야 합니다.

1. 모의투자로 충분히 검증합니다(최소 한 번 이상 사고-파는 사이클 확인).
2. `.env` 에서 `LIVE_TRADING_HARD_LOCK=false` 로 바꾸고 프로그램을 다시 실행합니다.
3. **업비트 API 연결** 탭 → **점검 항목 보기** → 모든 항목 ✓ 확인 → 출금 권한을 끈 것을 체크 → 확인 문구 입력 → **실전 매매 허용**
4. 실전으로 돌릴 봇을 **끈 상태에서** 카드 아래 "실전(LIVE)으로 전환" → 확인 문구 입력.
   - 이 봇을 켜는 순간부터 실제 업비트 계좌로 주문이 나갑니다.
   - 모의 기록과 섞이지 않도록, 코인을 들고 있는 봇은 모드를 바꿀 수 없습니다.

실전을 끄려면 **실전 끄기** (켜진 실전 봇을 모두 끄고 미체결 주문 취소, 보유 코인은 그대로).

## 8. 봇 만드는 방법

**새로운 코인 자동매매 봇 만들기 → 봇 세팅하기**

1. **코인 선택** — 빠른 선택 4개 또는 검색(업비트 원화 마켓 전체, 실시간 가격 표시)
2. **전략 선택** — 아래 3가지 중 하나. "세부 설정"을 펼치면 간격·기간 등을 바꿀 수 있습니다.
3. **목표 익절 / 손절 기준**
4. **예산** — 봇은 이 금액을 넘어서 사지 않습니다.
5. **봇 만들고 모의투자 시작**

봇 카드의 큰 스위치:
- **켜기**: 시세 감시 시작, 조건이 오면 주문
- **끄기**: 새 주문 중단 + **이 봇이 넣어둔 미체결 주문만 취소**. 가진 코인은 **팔지 않습니다.**

## 9. 전략 설명

| 전략 | 동작 | 기본값(변경: `server/config/strategyDefaults.ts`) |
|---|---|---|
| 🕸️ 무한 그물망(그리드) | 봇을 켤 때 가격을 기준가로, 아래로 간격(%)마다 "칸"을 만듭니다. 가격이 칸에 닿으면 그 칸 금액만큼 지정가로 사고, 산 가격 × (1 + 목표 익절%)에 팔도록 예약합니다. 칸마다 주문은 1개만(중복 주문 방지). 간격은 **고정** 또는 **최근 변동폭(ATR)에 맞춰 자동**. **하락장 매수 멈춤**: 60분봉 EMA50보다 3% 넘게 아래면 새로 사지 않고(익절 매도는 계속) 기다립니다. 들고 있는 칸이 없을 때 가격이 2칸 이상 오르면 기준가를 따라 올립니다. | 고정 1%, 5칸, 칸당 = 예산 ÷ 칸 수, 하락장 매수 멈춤 켬 |
| 📉 RSI 과매도 반등 | 닫힌 캔들 기준 RSI(Wilder). **반등 확인 매수(기본)**: RSI가 과매도선 아래로 내려갔다가 **다시 위로 올라오는 순간** 나눠서 시장가 매수 → 떨어지는 칼날을 잡지 않음. **추세 필터**: 종가가 EMA200 위(장기 상승 추세)일 때만 매수. 같은 하락에서 반복 매수하지 않고, 최대 횟수 제한. 과매수선 이상이면 전량 매도. | 15분봉, RSI 14, 30 / 70, 반등 확인, EMA200 필터, 1회 33% × 최대 3회 |
| 🚀 골든크로스 돌파 | 닫힌 캔들 기준 EMA(또는 SMA). "이전엔 단기 ≤ 장기, 지금은 단기 > 장기"인 **교차 순간에만**, 그리고 **거래량이 평소(20봉 평균)의 1.2배 이상**일 때만 매수(가짜 돌파 거르기). **변동폭(ATR) 손절**과 **트레일링 익절**로 관리. 데드크로스 순간 전량 매도. | 60분봉, EMA 9 / 21, 거래량 1.2배, ATR×2 손절, 트레일링 1.5% |

**익절 / 손절 기준 (공통)**
- 기준 가격 = **평균 매입가** = (체결금액 + 매수 수수료) ÷ 보유 수량 → 나눠 사면 평단이 바뀌고 그 평단으로 판단합니다.
- 수익률 = (현재가 − 평균 매입가) ÷ 평균 매입가. 매도 수수료는 판단에 넣지 않습니다.
- 손절선에 닿으면: 이 봇의 다른 미체결 주문을 먼저 취소 → 보유 수량 재확인 → 시장가 전량 매도 → **봇 자동 OFF**(하락 중 재매수 방지).
- 그리드는 칸마다 익절하므로 공통 익절은 쓰지 않고, 손절만 적용합니다.
- **변동폭(ATR) 손절**(골든크로스 기본): 처음 산 시점의 ATR(14) × 배수만큼 평단 아래를 손절가로 쓰되, 손절 %보다 멀어지지는 않아요(둘 중 가까운 쪽).
- **트레일링 익절**(골든크로스 기본 1.5%): 목표 익절에 닿아도 바로 팔지 않고, 최고가를 따라가다가 최고가에서 정한 %만큼 내려오면 팔아요(평단 위에서만).
- **하루 최대 손실**(기본 예산의 5%): 오늘(한국 시간) 확정 손실이 한도에 닿으면 그날은 새로 사지 않아요. 파는 건 계속해요.
- **손실 후 쉬는 시간**(기본 60~120분): 손실을 보고 판 직후에는 새로 사지 않아요.
- 급락하면 실제 체결가는 손절선보다 낮을 수 있습니다.
- 모든 값은 봇 만들기 → 2번 "세부 설정"에서 봇별로 바꿀 수 있어요. 기본값은 `server/config/strategyDefaults.ts` 한 곳에서 관리해요.

**수익 표시**
- 이미 팔아서 확정된 수익(실현손익) = 매도 금액 − 매도 수수료 − 그만큼의 평균 매입 원가
- 아직 안 판 코인의 현재 기준 손익(미실현) = 보유 수량 × 현재가 − 보유 원가
- 누적 수익률 = (실현 + 미실현) ÷ 봇 예산

## 10. 긴급 정지 방법

**가동 중인 봇** 탭 아래 **🛑 모든 자동매매 멈추기 → 전체 멈추기**
- 모든 봇 OFF, 새 주문 전면 차단, 봇들이 넣어둔 미체결 주문 취소
- **가진 코인은 팔지 않습니다.** (팔고 싶으면 업비트에서 직접)
- 해제: 같은 카드의 **긴급 정지 해제** → 봇은 꺼진 상태이니 필요한 봇만 다시 켜세요.
- 긴급 정지 상태는 저장되어 프로그램을 다시 켜도 유지됩니다.

## 11. 로그 확인 방법

- 터미널 화면에 실시간으로 나옵니다.
- 파일: `data/logs/bot-YYYY-MM-DD.log` (날짜는 한국 시간)
- API: http://127.0.0.1:8787/api/logs?limit=200 (태그별: `&tag=ORDER`)
- 태그: `[PRICE] [STRATEGY] [SIGNAL] [ORDER] [ORDER_FILLED] [ORDER_CANCEL] [POSITION] [RISK] [ERROR] [WEBSOCKET] [SYSTEM] [API]`
- 예) `[STRATEGY] bot#2 KRW-BTC RSI=28.4 → BUY_SIGNAL (ENTRY)` → `[ORDER] PAPER KRW-BTC BUY price ... identifier=PBOT-2-...` → `[ORDER_FILLED] ...`
- Secret Key·인증 토큰은 로그에 남지 않도록 자동으로 가려집니다(`***`).

## 12. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 화면에 "서버(백엔드)에 연결되지 않았어요" | 터미널에서 `npm run dev` 가 실행 중인지, 오류가 없는지 |
| "이 PC의 IP 주소가 ... 등록되어 있지 않아요" | 업비트 Open API 관리에서 허용 IP에 현재 공인 IP 추가 |
| "API Key 인증에 실패했어요" | Access/Secret Key 짝, 만료일(연결 테스트 결과에 표시) |
| "권한이 없습니다" | Key의 자산조회/주문조회/주문하기 권한 |
| 헤더가 "시세 연결 끊김/재연결 중" | 인터넷 연결. 자동으로 재연결합니다(간격을 점점 늘려 폭주 방지) |
| 봇이 주문을 안 함 | 시그널 탭의 "주문 안 함: 이유"(예산 초과, 최소 주문 금액 미달, 원화 부족 등) |
| 실전 점검 항목 실패 | 항목별 설명대로 해결 후 다시 확인 |

## 13. 실제 거래 전 체크리스트

프로그램이 자동으로 확인하는 항목(점검 항목 화면):
- [ ] 실전 하드락 해제(.env)
- [ ] API 인증 성공(최근 24시간 내 연결 테스트)
- [ ] 실제 잔고 조회 성공
- [ ] 주문 가능 정보 조회 / 주문 권한(주문 생성 테스트)
- [ ] 실시간 현재가(Public WebSocket) 정상
- [ ] myOrder / myAsset(Private WebSocket) 연결
- [ ] 긴급 정지 해제 상태
- [ ] 모의투자로 매수→매도 한 사이클 이상

사람이 직접 확인할 항목:

## 개발자용

| 명령 | 설명 |
|---|---|
| `npm run dev` | 백엔드(tsx watch) + 프론트(vite) |
| `npm test` | 단위 + PAPER 통합 테스트(네트워크 없음) |
| `npm run test:network` | 실제 업비트 공개 API/WS 테스트 (+ .env Key가 있으면 잔고·주문테스트 API, **실주문 없음**) |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 프론트 빌드 |

- 구조와 설계: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) · 진행 기록: [PROGRESS.md](PROGRESS.md)
- 구현 기준 문서: 업비트 개발자 센터 https://docs.upbit.com/kr (개발 중 받은 사본 `docs/upbit-reference/`는 저작권상 저장소에 포함하지 않음)
- 전략 기본값: `server/config/strategyDefaults.ts` 한 곳 · 화면 문구: `src/lib/labels.ts`
